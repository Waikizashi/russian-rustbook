# Как помочь проекту

Спасибо за интерес к дополнению. Здесь ценятся точность, понятные объяснения и небольшие проверяемые изменения. Весь основной учебный текст, issues и обсуждения можно вести на русском.

## С чего начать

- Уточнить формулировку, которая стала понятна только после нескольких прочтений.
- Исправить опечатку, ссылку или неверный ожидаемый результат.
- Добавить тест на граничное значение или некорректный вход.
- Предложить упражнение с объяснением, чему оно учит.

Для ошибки укажи главу, фрагмент и ожидаемое поведение. Если проблема в программе, приложи минимальный вход, версию Rust и вывод команды. Для большого нового раздела сначала полезно обсудить цель в issue.

## Подготовка

Нужны стабильный Rust с `rustfmt` и `clippy`, Python 3.11+, Git. Для сайта — mdBook 0.5.4; для EPUB — Pandoc. Rust-код поддерживает версии от 1.85 и редакцию 2024.

```sh
rustup component add rustfmt clippy
cargo install mdbook --version 0.5.4 --locked
```

Все Python-скрипты используют стандартную библиотеку. Для обычной проверки текста Pandoc и mdBook не нужны.

## Проверки перед pull request

Из корня репозитория:

```sh
python3 scripts/check.py
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --all-targets --locked
cargo test --workspace --release --locked
python3 scripts/run_examples.py
python3 scripts/run_examples.py --release
python3 scripts/prepare_book.py
mdbook build
mdbook test
```

`mdbook test` проверяет самостоятельные листинги. Четыре фрагмента проекта в главе 11 помечены `ignore`: они являются частями одной библиотеки и проверяются через Cargo. `scripts/check.py` дополнительно требует, чтобы текст этих фрагментов совпадал с исходником библиотеки.

## Как менять код в главах

У коротких примеров есть две формы: кодовый блок в главе и соответствующий файл в `examples/`. Скрипт проверяет их точное совпадение.

Можно изменить пример в Rust-файле, выполнить `cargo fmt --all`, затем перенести его в текст:

```sh
python3 scripts/sync_examples.py --to-docs
python3 scripts/check.py
```

Если изменён сам кодовый блок, `python3 scripts/sync_examples.py` перенесёт его в `examples/`. После форматирования синхронизируй обратно командой выше. Добавляя новый листинг, обнови сгенерированный список примеров тем же скриптом.

Код Byte Note находится в `crates/byte-note/src/lib.rs`. Комментарии `SECTION` и `END` обозначают четыре фрагмента для главы 11; сохраняй эти границы. Изменения формата должны сопровождаться обновлением спецификации, вектора байтов и тестов.

## Стиль текста

Пиши по-русски, объясняй новую идею перед её использованием. Для первого появления полезно дать английский термин в скобках, затем использовать устойчивую русскую формулировку. Различай байт, `char` и графему; числовое преобразование и представление; переполнение значения и чрезмерный сдвиг.

Избегай заявлений «безопасно», «работает везде», «без копирования» без указания границ. Если правило зависит от формата, архитектуры, версии или профиля сборки, скажи об этом рядом с примером. Для технических утверждений используй первичные источники: Rust Reference, стандартную библиотеку, RFC и официальные спецификации.

## Pull request и лицензия

Описывай проблему и то, как изменение помогает читателю. Укажи выполненные проверки. Небольшой PR проще проверить, чем одновременную переработку нескольких тем.

Вклад распространяется на условиях MIT, как остальной проект. Не добавляй чужие главы, иллюстрации и большие цитаты без подходящей лицензии и указания источника. Если использовал ИИ при подготовке изменения, укажи это и проверь факты и код самостоятельно.
