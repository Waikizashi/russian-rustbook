# 4. Число превращается в байты

<a id="byte-order"></a>

## Порядок байтов

Число `0x12345678` помещается в четыре байта. Чтобы записать их в файл, нужно решить, какой идёт первым.

| Представление | Байты по порядку |
|---|---|
| Big-endian, старший байт первым | `12 34 56 78` |
| Little-endian, младший байт первым | `78 56 34 12` |

Это **порядок байтов** (*endianness*). Само числовое значение в обоих случаях одинаково. В байте `0x12` по-прежнему тот же восьмибитный узор. Перестановка байтов не означает разворот битов внутри них.

Какой порядок использует процессор, важно для внутреннего представления. Какой порядок использует формат, важно для чтения файла или обмена сообщениями. Эти два решения не обязаны совпадать.

<a id="byte-conversion"></a>

## Явное преобразование в Rust

```rust
fn main() {
    let n = 0x1234_5678u32;
    assert_eq!(n.to_be_bytes(), [0x12, 0x34, 0x56, 0x78]);
    assert_eq!(n.to_le_bytes(), [0x78, 0x56, 0x34, 0x12]);

    let bytes = [0x01, 0x02];
    assert_eq!(u16::from_be_bytes(bytes), 258);
    assert_eq!(u16::from_le_bytes(bytes), 513);
}
```

`to_be_bytes` создаёт массив байтов в big-endian, `from_be_bytes` читает его по тому же правилу. Аналогичные методы с `le` используют little-endian. Они дают переносимый результат и не требуют `unsafe`.

Суффикс `ne` означает native endian: порядок текущей машины. Для постоянного файла или собственного сетевого формата обычно нужен фиксированный `be` или `le`. Если отправитель выбрал `to_ne_bytes`, а получатель работает на другой архитектуре, смысл может измениться.

Не путай `to_be()` и `to_be_bytes()`: первый возвращает целое, второй — массив `u8`. Когда нужны именно байты для записи, второй метод выражает намерение напрямую.

Справка: [`to_be_bytes`](https://doc.rust-lang.org/std/primitive.u32.html#method.to_be_bytes), [`from_le_bytes`](https://doc.rust-lang.org/std/primitive.u16.html#method.from_le_bytes).

<a id="fixed-width"></a>

## Почему `usize` не стоит сохранять в протокол

`usize` подходит для длины среза и индекса массива. Его ширина зависит от целевой платформы. Формат, в котором длина записана как «один `usize`», без дополнительных правил будет неоднозначным.

Для протокола выбери, например, **четыре байта, без знака, big-endian**. В программе прочитай их как `u32`, затем проверяемо преобразуй в `usize` и сравни с ограничением размера. Ограничение задаётся форматом или приложением, а не только вместимостью типа.

```rust
fn main() {
    let wire_length = 1024u32;
    let length = usize::try_from(wire_length).unwrap();
    const MAX_PAYLOAD: usize = 64 * 1024;
    assert!(length <= MAX_PAYLOAD);
    assert_eq!(wire_length.to_be_bytes(), [0, 0, 4, 0]);
}
```

Число может помещаться в `u32`, но быть неприемлемым для выделения памяти: пакет на несколько гигабайт тебе может быть не нужен. Проверка диапазона типа и проверка лимита решают разные задачи.

<a id="float-bits"></a>

## Дробные числа тоже имеют битовое представление

`f32` хранится в двоичном формате IEEE 754 binary32. Его 32 бита разделены на знак, показатель степени и дробную часть. Точное устройство нужно, например, для форматов изображений или научных данных. Для обычной математики используй операции над `f32`.

```rust
fn main() {
    let x = 1.0f32;
    assert_eq!(x.to_bits(), 0x3F80_0000);
    assert_eq!(x.to_bits().to_be_bytes(), [0x3F, 0x80, 0, 0]);
    assert_eq!(f32::from_bits(0x3F80_0000), 1.0);
    assert_eq!(1.5f32 as u32, 1);
    assert_ne!(1.5f32.to_bits(), 1);
}
```

`as u32` выполняет числовое преобразование. `to_bits()` возвращает представление. В формате обязательно уточняй, что передаётся: целое число или IEEE 754, какой ширины и в каком порядке байтов. Для `NaN` и бесконечностей могут понадобиться отдельные правила допустимости.

Справка: [`f32::to_bits`](https://doc.rust-lang.org/std/primitive.f32.html#method.to_bits), [`f32::from_bits`](https://doc.rust-lang.org/std/primitive.f32.html#method.from_bits).

**Проверь себя.** Значение `0x01020304u32` записано little-endian. Какие четыре байта увидишь в файле? Что получит читатель, ошибочно использующий big-endian? Чем отличается разворот байтов от разворота битов?
