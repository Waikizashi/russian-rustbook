# 12. Упражнения и решения

<a id="answers-basics"></a>

## Ответы к разделам 1–4

**Раздел 1.** 40 бит — 5 байтов. `1010_0110` равно `128 + 32 + 4 + 2 = 166`. В hex 255 — `FF`, 256 — `100`. Последнее значение уже не помещается в один байт.

**Раздел 2.** Сдвиг `128u8 << 1` теряет старший бит и даёт 0; `checked_mul(2)` проверяет числовой диапазон и возвращает `None`. Представление −2 в `i8` — `1111_1110`. У `300u16 as u8` остаются младшие восемь битов, то есть 44.

**Раздел 3.** Сброс бита 3: `value &= !(1u8 << 3)`. Для `flags = 001` и `mask = 011` есть хотя бы один запрошенный флаг, но нет всех. Версия 2 и тип 9 дают `(2 << 5) | 9 = 73`, то есть `0100_1001` или `49` в hex.

**Раздел 4.** Little-endian-байты числа `0x01020304`: `04 03 02 01`. Если прочитать их как big-endian, получится `0x04030201`. Разворот байтов переставляет восьмибитные группы; разворот битов меняет порядок всех битовых позиций.

<a id="answers-data"></a>

## Ответы к разделам 5–10

**Раздел 5.** `with_capacity(100)` оставляет длину 0, а `vec![0u8; 100]` создаёт 100 инициализированных нулевых байтов. В `offset + 2` возможен выход за диапазон `usize` до сравнения с длиной буфера; нужен `checked_add`.

**Раздел 6.** `"Я!"` занимает 3 байта: два у `Я`, один у `!`. Число `char` не равно числу видимых графем во всех текстах. `D0` имеет префикс начала двухбайтовой UTF-8-последовательности, но продолжения нет; это усечённый ввод.

**Раздел 7.** В `[1, 0, 0, 0, 9]` заявлена пустая нагрузка, но остался байт `9`, поэтому возвращается `TrailingBytes`. Для последовательности можно вернуть разобранное сообщение и непрочитанный срез. Два противоположных преобразования могут разделять одну ошибку, поэтому нужен независимый вектор байтов.

**Раздел 8.** 301 кодируется как `AD 02`: `301 = 45 + 2 × 128`. У максимального `u64` 64 значащих бита; для семибитных групп нужно 10 байтов. Base64 обратима без секретного ключа и не обеспечивает конфиденциальность.

**Раздел 9.** TCP сохраняет последовательность байтов; границы чтений и записей могут отличаться. Лимит проверяют до выделения буфера, чтобы отвергнуть недопустимый запрос памяти. При уничтожении `BufReader` можно потерять уже прочитанные им байты, которые приложение ещё не использовало.

**Раздел 10.** Выравнивание может добавить промежутки между полями и в конце. `repr(C)` не задаёт переносимый порядок байтов и не инициализирует padding. CRC не обнаруживает абсолютно все возможные изменения и не доказывает, кто отправитель.

## Задача A. Битовый набор

В `u64` хранятся признаки для 64 объектов. Напиши функции проверки и установки по индексу. Индексы вне 0–63 должны возвращать `None`. Не допускай чрезмерного сдвига.

Решение:

```rust
fn contains(set: u64, index: u32) -> Option<bool> {
    let mask = 1u64.checked_shl(index)?;
    Some(set & mask != 0)
}

fn insert(set: u64, index: u32) -> Option<u64> {
    let mask = 1u64.checked_shl(index)?;
    Some(set | mask)
}

fn main() {
    let set = insert(0, 63).unwrap();
    assert_eq!(contains(set, 63), Some(true));
    assert_eq!(contains(set, 0), Some(false));
    assert_eq!(insert(set, 64), None);
    assert_eq!(set.count_ones(), 1);
}
```

Здесь `checked_shl` подходит точно: сдвигается единственная единица, а проверять нужно допустимость позиции. Ограничение о потере старших битов из раздела 2 не мешает, потому что исходное значение равно 1.

## Задача B. Упаковка цвета

Задай числовое представление цвета `0xRRGGBBAA`: четыре канала по восемь битов. Собери его из отдельных `u8`, затем извлеки зелёный канал. Значения каналов: `12 34 56 FF` в hex.

```rust
fn main() {
    let (r, g, b, a) = (0x12u8, 0x34u8, 0x56u8, 0xFFu8);
    let color = (u32::from(r) << 24) | (u32::from(g) << 16) | (u32::from(b) << 8) | u32::from(a);
    assert_eq!(color, 0x1234_56FF);
    assert_eq!(((color >> 16) & 0xFF) as u8, g);
    assert_eq!(color.to_be_bytes(), [r, g, b, a]);
}
```

Сначала каналы расширены до `u32`, поэтому сдвиг на 24 допустим. У `u8` такой сдвиг недопустим. Имя «RGBA» само по себе не гарантирует конкретное числовое представление или байтовый порядок чужого API: их нужно проверять по его документации.

## Задача C. Массив двухбайтовых чисел

Буфер содержит последовательность `u16` в big-endian. Отклони нечётную длину, а чётную разбери без `unsafe`.

```rust
fn read_values(data: &[u8]) -> Option<Vec<u16>> {
    if data.len() % 2 != 0 {
        return None;
    }
    Some(
        data.chunks_exact(2)
            .map(|p| u16::from_be_bytes([p[0], p[1]]))
            .collect(),
    )
}

fn main() {
    assert_eq!(read_values(&[0, 1, 1, 0]), Some(vec![1, 256]));
    assert_eq!(read_values(&[]), Some(vec![]));
    assert_eq!(read_values(&[0]), None);
}
```

Проверка нечётной длины не позволяет молча потерять последний байт. `chunks_exact(2)` даёт части ровно по два элемента; после проверки они полностью покрывают вход.

<a id="exercise-rotate"></a>

## Задача D. Сдвиги и циклический сдвиг

Предскажи результаты для `1001_0000u8`: обычный сдвиг влево на 2 и циклический сдвиг влево на 2.

```rust
fn main() {
    let n = 0b1001_0000u8;
    assert_eq!(n << 2, 0b0100_0000);
    assert_eq!(n.rotate_left(2), 0b0100_0010);
}
```

Обычный сдвиг отбросил два старших бита `10`. Циклический вернул их в две младшие позиции.

## Задача E. Предскажи байты Byte Note

Для пустой бинарной нагрузки, `kind = 0`, `flags = 0`, `sequence = 1` какие первые 12 байтов создаст кодировщик? Какой длины полное сообщение?

Ответ: `42 59 54 45 20 00 00 00 01 00 00 00`; полный размер — 16 байтов. Включение `UTF8` при пустой нагрузке тоже допустимо: пустая строка является корректным UTF-8.

## Задача F. Найди ошибку в подходе

1. Длина пришла из сети; программа сначала выделила буфер, затем проверила лимит.
2. Полученные двоичные данные преобразовали через `from_utf8_lossy`, а затем сохранили как исходные.
3. Маску нескольких флагов проверили через `!= 0`, хотя требовалось наличие всех.
4. Один `read` посчитали полным сообщением после одного `write_all` отправителя.
5. Структуру с padding записали в файл как сырые байты.

Во всех пяти случаях нарушено правило интерпретации или проверки. Исправления: лимит до выделения; сохранение исходных байтов; сравнение с полной маской; явное кадрирование; поэлементная сериализация полей.
