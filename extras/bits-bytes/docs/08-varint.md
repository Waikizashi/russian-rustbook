# 8. Числа переменной длины и текстовое представление байтов

<a id="varint-idea"></a>

## Зачем числу разная длина

Если счётчики почти всегда маленькие, запись каждого как восьмибайтового `u64` расходует много места. **Varint** — общее название способов записывать целое переменным числом байтов. Ниже используется вариант unsigned LEB128: младшие семибитные группы идут первыми.

У каждого байта младшие семь битов содержат данные. Старший бит равен 1, если следом идёт ещё группа, и 0 у последнего байта.

| Число | Байты в hex | Почему |
|---:|---|---|
| 0 | `00` | Одна нулевая группа |
| 127 | `7F` | Семь битов помещаются в один байт |
| 128 | `80 01` | Младшая группа 0, следующая 1 |
| 300 | `AC 02` | `44 + 2 × 128 = 300` |

Это правило группировки битов, а не простая запись `to_le_bytes` без нулевых байтов. Для крупных `u64` оно может потребовать десять байтов — больше, чем фиксированные восемь. Компактность зависит от распределения значений.

<a id="varint-code"></a>

## Кодировщик и декодер

```rust
#[derive(Debug, PartialEq, Eq)]
enum VarintError {
    Truncated,
    Overflow,
    NonCanonical,
}

fn encode(mut n: u64) -> Vec<u8> {
    let mut out = Vec::new();
    loop {
        let mut byte = (n & 0x7F) as u8;
        n >>= 7;
        if n != 0 {
            byte |= 0x80;
        }
        out.push(byte);
        if n == 0 {
            return out;
        }
    }
}

fn decode(data: &[u8]) -> Result<(u64, usize), VarintError> {
    let mut value = 0u64;
    for i in 0..10usize {
        let byte = *data.get(i).ok_or(VarintError::Truncated)?;
        if i == 9 && byte > 1 {
            return Err(VarintError::Overflow);
        }
        let group = byte & 0x7F;
        value |= u64::from(group) << (7 * i);
        if byte & 0x80 == 0 {
            if i > 0 && group == 0 {
                return Err(VarintError::NonCanonical);
            }
            return Ok((value, i + 1));
        }
    }
    Err(VarintError::Overflow)
}

fn main() {
    assert_eq!(encode(300), [0xAC, 0x02]);
    assert_eq!(decode(&[0xAC, 0x02, 0x99]), Ok((300, 2)));
    for n in [0, 1, 127, 128, 300, u64::MAX] {
        let bytes = encode(n);
        assert_eq!(decode(&bytes), Ok((n, bytes.len())));
    }
    assert_eq!(decode(&[0x80]), Err(VarintError::Truncated));
    assert_eq!(decode(&[0x80, 0]), Err(VarintError::NonCanonical));
    assert_eq!(decode(&[0xFF; 10]), Err(VarintError::Overflow));
}
```

Десятая семибитная группа начинается на позиции 63. В `u64` остаётся только один бит; поэтому последний байт допускает значения 0 или 1, а продолжение на этой позиции запрещено. Проверять только число итераций недостаточно: нужно проверить и значение десятого байта.

Результат содержит число прочитанных байтов, чтобы следующий парсер мог продолжить с `&data[used..]`. Хвост сам по себе не считается ошибкой: декодер читает одно число из начала последовательности.

**Каноническая запись** — кратчайшая допустимая. Наш декодер отклоняет `80 00`, хотя такой набор можно арифметически истолковать как ноль. Это выбранное правило данного примера. У другого формата политика может быть иной. Для совместимости нужно следовать его спецификации.

<a id="zigzag"></a>

## А что делать с отрицательными числами

Отрицательное число в дополнительном коде имеет много единиц в старших разрядах. Если сначала привести его к `u64`, маленькое отрицательное значение перестанет быть маленьким беззнаковым числом.

Кодирование **ZigZag** сопоставляет `0 → 0`, `−1 → 1`, `1 → 2`, `−2 → 3`, `2 → 4`. После него можно применить unsigned varint. Это отдельное преобразование; обычное двоичное представление `i64` оно не заменяет.

Оба приёма встречаются, например, в Protocol Buffers. Наш листинг — учебный самостоятельный вариант, а не полный парсер этого протокола. Справка: [официальное описание двоичного кодирования Protocol Buffers](https://protobuf.dev/programming-guides/encoding/).

<a id="base64"></a>

## Hex и Base64 решают другую задачу

Hex превращает каждый байт в две ASCII-цифры: `[0xDE, 0xAD]` станет текстом `"DEAD"`. Base64 собирает три байта в 24 бита и делит их на четыре группы по шесть битов. Каждая группа выбирает символ из алфавита длиной 64.

Для ASCII-текста `Man` байты равны `4D 61 6E`. Шестибитные группы имеют значения 19, 22, 5, 46; в стандартном алфавите это `T`, `W`, `F`, `u`. Получается `TWFu`.

Для неполной последней группы стандартная Base64 с padding добавляет `=`: `M` кодируется как `TQ==`, а `Ma` как `TWE=`. Base64url использует другой вариант алфавита; наличие padding определяется конкретным форматом.

Base64 не шифрует и обычно увеличивает размер: при стандартном padding выход имеет `4 × ceil(n / 3)` ASCII-символов. Она нужна, когда произвольные байты требуется передать через текстовое поле. Varint уменьшает запись некоторых чисел; Base64 обеспечивает текстовое представление произвольных байтов. Эти задачи разные.

Справка: [RFC 4648, разделы 4 и 5](https://www.rfc-editor.org/rfc/rfc4648.html#section-4).
