# 2. Числа: знак, переполнение и сдвиги

<a id="signed"></a>

## Одинаковые биты, разные типы

У `u8` нет знака: восемь битов отведены под значение 0–255. У `i8` диапазон −128–127. Знаковые целые в Rust используют **дополнительный код** (*two's complement*). Для восьми битов старшая позиция имеет вес −128, остальные — положительные веса 64, 32, 16, 8, 4, 2, 1.

Поэтому `1111_1111` как `u8` означает 255, а как `i8` — `−128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = −1`. Число `1000_0000` как `i8` означает −128.

Чтобы получить дополнительный код −5 в восьми битах, возьми код +5 (`0000_0101`), инвертируй биты (`1111_1010`) и прибавь единицу (`1111_1011`). Это способ объяснить представление; для обычной арифметики Rust сам выполняет нужные операции.

```rust
fn main() {
    let bits = 0xFFu8;
    assert_eq!(bits, 255);
    assert_eq!(bits as i8, -1);
    assert_eq!((-5i8) as u8, 0b1111_1011);
    assert_eq!(i8::MIN, -128);
    assert_eq!(i8::MAX, 127);
}
```

`as` здесь меняет интерпретацию одного и того же восьмибитного узора. В общем случае приведение целого через `as` может отбросить старшие биты. Если значение пришло извне и должно помещаться без потерь, используй проверяемое преобразование:

```rust
fn main() {
    assert_eq!(u8::try_from(200u16), Ok(200));
    assert!(u8::try_from(300u16).is_err());
    assert_eq!(300u16 as u8, 44);
    assert!(u8::try_from(-1i32).is_err());
}
```

После отбрасывания старшего байта от 300 остаётся 44: `300 = 256 + 44`. Это допустимая семантика `as`, но для длины пакета такой результат обычно означает ошибку в программе.

Справка: [`i8`](https://doc.rust-lang.org/std/primitive.i8.html), [приведения целых](https://doc.rust-lang.org/reference/expressions/operator-expr.html#numeric-cast).

<a id="overflow"></a>

## Переполнение должно быть осознанным

Математическая сумма `250 + 10` равна 260. В `u8` она не помещается. Rust предоставляет методы, позволяющие прямо выбрать правило:

| Метод | Результат для `250u8 + 10` | Типичный смысл |
|---|---|---|
| `checked_add` | `None` | Отказать при выходе за диапазон |
| `wrapping_add` | `4` | Считать по модулю 256 |
| `saturating_add` | `255` | Ограничить максимальным значением |
| `overflowing_add` | `(4, true)` | Получить результат и признак переполнения |

```rust
fn main() {
    let x = 250u8;
    assert_eq!(x.checked_add(10), None);
    assert_eq!(x.wrapping_add(10), 4);
    assert_eq!(x.saturating_add(10), 255);
    assert_eq!(x.overflowing_add(10), (4, true));
}
```

Обычный `+` зависит от настройки проверок переполнения: в стандартном профиле разработки проверки включены и переполнение вызывает панику; в стандартном release-профиле они выключены и обычное сложение оборачивается. Профили можно переопределить. Явный метод делает правило понятным независимо от профиля.

Для размеров, смещений и счётчиков выделяемой памяти обычно подходит `checked_*`. `wrapping_*` нужен там, где вычисления по модулю являются частью алгоритма. `saturating_*` удобен для величин, которые должны остановиться на границе диапазона.

Справка: [`checked_add`](https://doc.rust-lang.org/std/primitive.u8.html#method.checked_add), [проверки переполнения в Cargo](https://doc.rust-lang.org/cargo/reference/profiles.html#overflow-checks).

<a id="shifts"></a>

## Сдвиг: перемещаем позиции

`x << k` сдвигает биты влево на `k` позиций, `x >> k` — вправо. У беззнакового целого освободившиеся позиции заполняются нулями. Биты, вышедшие за ширину типа, теряются.

```rust
fn main() {
    assert_eq!(0b0000_1101u8 << 2, 0b0011_0100);
    assert_eq!(0b0000_1101u8 >> 2, 0b0000_0011);
    assert_eq!(0b1000_0001u8 << 1, 0b0000_0010);

    assert_eq!(1u8.checked_shl(7), Some(128));
    assert_eq!(1u8.checked_shl(8), None);
    assert_eq!(128u8.checked_shl(1), Some(0));

    assert_eq!(-3i8 >> 1, -2);
    assert_eq!(-3i8 / 2, -1);
}
```

В первых строках сдвиг 13 влево на 2 даёт 52. Но правило «сдвиг равен умножению на степень двойки» требует, чтобы результат помещался в тип. У 129 при сдвиге влево один старший бит исчезает, и остаётся 2.

**Тонкость `checked_shl`:** метод проверяет величину сдвига, а не сохранность старших битов. Поэтому `128u8.checked_shl(1)` возвращает `Some(0)`. Если нужна проверяемая арифметика, используй, например, `checked_mul(2)`.

У знакового целого сдвиг вправо повторяет знаковый бит. Из-за этого отрицательное число может округлиться иначе, чем при делении: −3 сдвигается в −2, а целочисленное деление −3 / 2 округляет к нулю и даёт −1.

Входную величину сдвига проверяй: для `u8` допустимы 0–7, для `u32` — 0–31. Поведение обычного оператора при чрезмерном сдвиге не должно служить правилом формата. Для внешних данных подходят `checked_shl` и `checked_shr`.

Справка: [операторы сдвига](https://doc.rust-lang.org/reference/expressions/operator-expr.html#arithmetic-and-logical-binary-operators), [`checked_shl`](https://doc.rust-lang.org/std/primitive.u32.html#method.checked_shl).
