# 5. Буферы, массивы и срезы байтов

<a id="buffer-types"></a>

## Какой тип выбрать

Двоичные данные в Rust обычно представлены одним из трёх способов:

| Тип | Что означает | Когда удобен |
|---|---|---|
| `[u8; N]` | Массив ровно из `N` байтов | Фиксированный заголовок, число, идентификатор |
| `Vec<u8>` | Владеющий буфер переменной длины | Сборка сообщения, чтение файла |
| `&[u8]` | Заимствованное представление последовательности | Разбор уже полученных данных без копии |

`&mut [u8]` позволяет менять байты в чужом буфере. У среза есть длина, но он не владеет памятью. Функция, принимающая `&[u8]`, может прочитать и массив, и вектор, и часть другого среза.

```rust
fn main() {
    let mut bytes = Vec::with_capacity(8);
    assert_eq!(bytes.len(), 0);
    assert!(bytes.capacity() >= 8);
    bytes.extend_from_slice(&[0xAB, 0xCD]);
    bytes.push(0xEF);
    assert_eq!(bytes.as_slice(), &[0xAB, 0xCD, 0xEF]);

    let header: &[u8] = &bytes[..2];
    assert_eq!(header, &[0xAB, 0xCD]);

    let initialized = vec![0u8; 8];
    assert_eq!(initialized.len(), 8);
}
```

**Длина** (`len`) — число существующих элементов. **Вместимость** (`capacity`) — сколько элементов можно разместить без перераспределения памяти. `with_capacity(8)` не создаёт восемь доступных байтов: длина остаётся нулевой. Для буфера, который нужно сразу заполнить чтением, подходит `vec![0u8; 8]`.

Срез `&bytes[..2]` не копирует байты. Пока это заимствование используется, Rust не позволит выполнить конфликтующую операцию, например изменить вектор так, что его данные переедут в другую область памяти.

Справка: [гарантии `Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#guarantees), [`with_capacity`](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.with_capacity), [срезы](https://doc.rust-lang.org/std/primitive.slice.html).

<a id="bounds"></a>

## Границы нужно проверять

При известной длине выражение `&data[2..4]` удобно. Если длина пришла из файла или сети, такой срез может вызвать панику. `get` возвращает `Option`, поэтому недостаток данных можно превратить в обычную ошибку.

```rust
fn read_u16_at(data: &[u8], offset: usize) -> Option<u16> {
    let end = offset.checked_add(2)?;
    let part = data.get(offset..end)?;
    Some(u16::from_be_bytes([part[0], part[1]]))
}

fn main() {
    let data = [0xAA, 0x01, 0x02];
    assert_eq!(read_u16_at(&data, 1), Some(258));
    assert_eq!(read_u16_at(&data, 2), None);
    assert_eq!(read_u16_at(&data, usize::MAX), None);
}
```

Сначала проверяется сложение смещения и длины, затем диапазон внутри буфера. После успешного `get` известно, что `part` содержит ровно два байта, поэтому индексы 0 и 1 допустимы.

Без `checked_add` само вычисление конца диапазона способно переполниться раньше, чем код проверит границы среза. Эту ошибку особенно легко пропустить, если все тестовые смещения маленькие.

<a id="hexdump"></a>

## Просмотр данных в hex

Когда парсер читает неожиданные значения, сначала посмотри на реальные байты. Компактный hex dump показывает смещение и содержимое:

```rust
fn main() {
    let data = b"Rust\x00\xFF";
    for (row, chunk) in data.chunks(8).enumerate() {
        print!("{:04X}: ", row * 8);
        for byte in chunk {
            print!("{byte:02X} ");
        }
        println!();
    }
}
```

Результат:

```text
0000: 52 75 73 74 00 FF
```

`b"..."` — байтовый строковый литерал. Он удобен для ASCII и явных байтовых escape-последовательностей. Для русского текста используй обычную строку и `.as_bytes()`. `b'R'` — один байт со значением `0x52`, а `'R'` — значение типа `char`.

В hex dump нельзя по виду данных доказать их смысл. `52 75 73 74` может быть ASCII-словом, частью сжатого блока или четырёхбайтовым числом. Подсказку даёт формат, а не сама hex-запись.

**Проверь себя.** Чем `Vec::with_capacity(100)` отличается от `vec![0u8; 100]`? Почему проверка `offset + 2 <= data.len()` без `checked_add` недостаточна для произвольного `offset`?
