# 6. Байты и текст: ASCII, Unicode, UTF-8

<a id="encoding"></a>

## Символ и его кодировка

**Unicode** присваивает символам кодовые точки, например `U+0041` для `A` и `U+0416` для `Ж`. **Кодировка** определяет, как представить эти значения в байтах. UTF-8 — одна из кодировок Unicode.

ASCII описывает 128 значений, от 0 до 127: латинские буквы, цифры, знаки и управляющие коды. В UTF-8 этот диапазон записывается теми же одиночными байтами. Поэтому слово `Rust` занимает четыре байта. Многие русские буквы занимают два, а `🦀` — четыре.

```rust
fn main() {
    assert_eq!(b'A', 65);
    assert_eq!(b'0', 48);
    assert_eq!("Ж".as_bytes(), &[0xD0, 0x96]);
    assert_eq!("🦀".as_bytes(), &[0xF0, 0x9F, 0xA6, 0x80]);

    let s = "AЖ🦀";
    assert_eq!(s.len(), 7);
    assert_eq!(s.chars().count(), 3);
    assert_eq!(std::mem::size_of::<char>(), 4);
}
```

`str::len()` считает байты. `chars().count()` считает скалярные значения Unicode. `char` в Rust занимает четыре байта как отдельное значение, но при добавлении в UTF-8-строку кодируется одним–четырьмя байтами.

Кодовая точка и скалярное значение — близкие, но не идентичные понятия: значения в диапазоне суррогатов Unicode не являются допустимыми значениями Rust `char`. Для работы со строками чаще достаточно помнить, что `char` — не обязательно целая видимая буква.

Справка: [`char`](https://doc.rust-lang.org/std/primitive.char.html), [`str::len`](https://doc.rust-lang.org/std/primitive.str.html#method.len), [Unicode: UTF и BOM](https://www.unicode.org/faq/utf_bom.html).

<a id="utf8-bits"></a>

## Почему `Ж` — это `D0 96`

У двухбайтовой UTF-8-последовательности вид `110xxxxx 10xxxxxx`. Префиксы обозначают начало и продолжение, а `x` содержат биты скалярного значения.

Код `Ж` — `U+0416`, то есть 1046. Его одиннадцать значащих позиций: `10000 010110`. Подставляем группы в шаблон:

| Часть | Шаблон | Биты `Ж` | Полученный байт |
|---|---|---|---|
| Первый байт | `110xxxxx` | `10000` | `11010000` = `D0` |
| Второй байт | `10xxxxxx` | `010110` | `10010110` = `96` |

Одиночный ASCII-байт выглядит как `0xxxxxxx`; трёхбайтовая последовательность — `1110xxxx 10xxxxxx 10xxxxxx`; четырёхбайтовая — `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx`.

Шаблонов недостаточно для полной проверки UTF-8: нужно также отклонять лишние удлинённые формы, суррогаты и значения вне допустимого диапазона. Для реальных данных используй проверку стандартной библиотеки. Разбор `Ж` нужен для понимания, а не как инструкция писать собственный декодер.

У UTF-8 нет отдельного порядка big-endian/little-endian: это последовательность байтов с фиксированными правилами. Запись `D0 96` нельзя переставить в `96 D0` и сохранить букву. У UTF-16, где используются 16-битные кодовые единицы, вопрос порядка байтов уже возникает.

<a id="text-boundaries"></a>

## Срез может пройти посередине буквы

```rust
fn main() {
    let s = "AЖ🦀";
    assert_eq!(s.get(1..3), Some("Ж"));
    assert_eq!(s.get(1..2), None);
    assert_eq!(&s.as_bytes()[1..2], &[0xD0]);

    let decomposed = "e\u{301}";
    assert_eq!(decomposed.chars().count(), 2);
    assert_eq!(decomposed.len(), 3);
}
```

У байтового среза можно взять любой допустимый диапазон. У `&str` границы обязаны совпадать с границами UTF-8-символов. `get` аккуратно возвращает `None`, а прямой строковый срез с неверной границей вызывает панику.

`e` плюс комбинируемое ударение выглядит как одна буква, но содержит два `char`. Видимая единица текста называется **графемным кластером**. Для курсора текстового редактора обычно нужны графемы, для двоичного протокола — число байтов. Это разные задачи.

Справка: [байты, скалярные значения и графемы в Rust Book](https://doc.rust-lang.org/book/ch08-02-strings.html#bytes-scalar-values-and-grapheme-clusters), [`str::get`](https://doc.rust-lang.org/std/primitive.str.html#method.get).

<a id="validate-text"></a>

## Полученные байты ещё не строка

```rust
fn main() {
    let valid = [0xD0, 0x96];
    assert_eq!(std::str::from_utf8(&valid).unwrap(), "Ж");

    let invalid = vec![0xFF];
    assert!(std::str::from_utf8(&invalid).is_err());
    assert_eq!(String::from_utf8_lossy(&invalid), "\u{FFFD}");
}
```

`from_utf8` проверяет данные и даёт заимствованный `&str`. `String::from_utf8` проверяет владеющий `Vec<u8>` и превращает его в `String`. Вариант `from_utf8_lossy` заменяет некорректные последовательности символом замены `�`; это полезно для отображения повреждённых данных, но изменяет содержимое.

Если формат требует точный UTF-8-текст, возвращай ошибку при нарушении кодировки. Если данные — картинка, архив или произвольный идентификатор, сохраняй их как байты. Отсутствие UTF-8 там может быть совершенно нормальным.

Для чтения сетевого текста сначала выдели полное сообщение. Одна UTF-8-последовательность может оказаться разделена между двумя вызовами `read`. Проверять каждый полученный кусок как самостоятельную строку неправильно.

Справка: [`from_utf8`](https://doc.rust-lang.org/std/str/fn.from_utf8.html), [`from_utf8_lossy`](https://doc.rust-lang.org/std/string/struct.String.html#method.from_utf8_lossy).
