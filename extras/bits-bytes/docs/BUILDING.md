# Сборка и публикация

## Источник текста

Канонические главы находятся в `docs/00-about.md` — `docs/13-reference.md`. Их можно читать прямо на GitHub. Якоря заданы HTML-тегами `<a id="..."></a>`, а ссылки между главами содержат имя Markdown-файла.

`python3 scripts/check.py` проверяет оглавление, существование локальных файлов и якорей, отсутствие незаполненных шаблонов и соответствие примеров. `python3 scripts/sync_examples.py --to-docs` переносит отформатированный Rust-код в текст.

## Сайт

```sh
python3 scripts/prepare_book.py
mdbook build
```

Подготовка создаёт временную `.book-src/`. В ней ссылки за пределы книги направлены в репозиторий, а составные фрагменты библиотеки отмечены для правильной обработки rustdoc. Готовый сайт находится в `book/`; исходные главы остаются удобными для чтения на GitHub.

Для локального просмотра: `mdbook serve --open`. Для сборки используется mdBook **0.5.4**. Его версия фиксируется в CI и инструкции, чтобы обновление генератора не меняло поведение неожиданно.

## EPUB и единый Markdown

Требуется Pandoc 3.x:

```sh
python3 scripts/build_ebooks.py
python3 scripts/verify_epub.py
```

Выход: `dist/Rust_Book_Bits_Bytes_RU_2026.epub` и одноимённый `.md`. В EPUB включены русский язык, название, сведения о проекте, дата сборки, оглавление и весь учебный текст. Код переносится из тех же глав. Внутренние ссылки преобразуются в локальные переходы; внешние страницы не включаются целиком.

`verify_epub.py` проверяет ZIP, MIME, XML, spine, локальные ссылки и соответствие кодовых блоков исходному Markdown. При установленном EPUBCheck дополнительно запусти `epubcheck dist/Rust_Book_Bits_Bytes_RU_2026.epub`.

PDF не является обязательным артефактом этого репозитория. Его можно экспортировать из HTML/EPUB средствами читалки; основная офлайн-версия — EPUB.

## GitHub Actions

- `ci.yml`: тесты Rust на MSRV и stable, форматирование, Clippy, исполнение примеров, сборка сайта и EPUB.
- `pages.yml`: публикация mdBook при изменении `main`, если GitHub Pages включён с источником GitHub Actions.
- `release.yml`: при теге `v*` повторяет проверки и публикует EPUB, Markdown, контрольные суммы и ZIP исходников в GitHub Releases.
- `links.yml`: отдельная еженедельная проверка внешних ссылок с тайм-аутами и повторными попытками.

Для Pages владелец репозитория выбирает **Settings → Pages → Source → GitHub Actions**. Первый публичный адрес появляется после успешного workflow; наличие файла workflow само по себе не означает, что сайт уже опубликован.

Для релиза владелец после просмотра изменений создаёт тег, например `git tag v1.0.0` и `git push origin v1.0.0`. Создание release требует `contents: write`; это разрешение выдаётся только соответствующей задаче workflow.
