# Сопровождение книги и сайта

## Оригинал и перевод

Основной процесс уже описан в [UPDATING.md](UPDATING.md); не заменяйте его копированием английских файлов поверх `src/`. В [ARCHITECTURE.md](ARCHITECTURE.md) перечислены границы данных, перевода и дополнения.

Еженедельный workflow `upstream.yml` сравнивает текущий официальный commit с `upstream.json`. При изменениях создаёт артефакт `upstream-status` с отчётом, diff по главам и кандидатом новой версии. Используется закреплённый Pandoc 3.13. Workflow имеет только чтение, не исполняет код оригинала, не принимает новый снимок и не создаёт фиктивно переведённых глав. PR с переводом открывает редактор после содержательной проверки.

Краткая последовательность:

```sh
git switch -c update-rustbook
python3 scripts/upstream.py prepare --ref HEAD --output .updates/next
# Прочитать REPORT.md и diffs, обновить только затронутые русские главы.
python3 scripts/upstream.py review --plan .updates/next ИМЯ_ГЛАВЫ.md
python3 scripts/check_book.py --candidate .updates/next
python3 scripts/upstream.py accept --plan .updates/next
python3 scripts/build_site.py
```

Проверяйте новые главы, изменения вложенности, include-зависимости, рисунки и код/диагностику. Подготовка и принятие не перезаписывают существующий русский текст; принятие запрещено до явной проверки всех затронутых глав. Сохраняйте локальные дополнения. Не удаляйте переведённую главу при исчезновении из оригинала без отдельного решения о её архивировании и старых ссылках.

## Дополнение

`extras/bits-bytes/docs/` — самостоятельный учебник; `src/supplement.md` связывает его с основной книгой. `prepare_book.py` готовит временную `.book-src`, её вручную не редактируют. Проверяйте примеры и тесты Cargo, затем запускайте общий сборщик сайта. Изменения оригинала не должны автоматически переписывать дополнение.

## SEO и публикация

После новой главы sitemap и стандартные метаданные формируются автоматически из сборки. Вручную проверьте первый абзац и описание: для специфической темы может потребоваться переопределение в `config/seo.json`. Устаревшие overrides удаляйте после проверки URL; сами главы и адреса без необходимости не переименовывайте. Токены Google/Bing сохраняйте при обновлениях.

Порядок публикации и отката — [DEPLOYMENT.md](DEPLOYMENT.md), диагностика индексации — [SEO.md](SEO.md). После объединения PR main автоматически проходит все проверки и публикуется. Проверяйте реальный deployment, а не только факт изменения workflow.

## Зависимости и артефакты

Обновляйте mdBook, Pandoc, EPUBCheck и Actions отдельными PR. Сверяйте официальный источник, версию, SHA-256 архивов и commit SHA Actions. После обновления запускайте сайт, проверки перевода/обновления, EPUB и примеры дополнения. Не отключайте проверки checksum или ошибок ради успешной публикации.

`book/`, `dist/`, `.tools/`, `.cache/`, `.updates/`, `.book-src/`, Cargo target и офлайн-файлы `downloads/*.epub|pdf|md|zip` исключены из Git. Снимок `upstream/en`, контрольные данные, лицензии и исходные иллюстрации — необходимые исходные материалы, их не удаляют как «сгенерированные файлы». Пользовательские EPUB/PDF публикуются через Releases; пока выпуска нет, не обещайте доступные файлы по отсутствующим ссылкам.

Лицензии оригинала, русской основы и собственного дополнения сохранены. При новых заимствованиях обновляйте [NOTICE.md](../NOTICE.md) и соответствующие уведомления, не приписывайте проекту авторство оригинала.
