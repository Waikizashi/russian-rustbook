# SEO и индексация

Адрес книги: https://waikizashi.github.io/russian-rustbook/.

## Сборка и метаданные

Команда `python3 scripts/build_site.py` собирает основную книгу и дополнение, затем запускает `site_seo.py`, `check_site.py` и `check_seo.py`. Непроверенный результат не публикуется. Один `mdbook build` создаёт только промежуточную основную книгу и **не** выполняет весь процесс публикации.

`config/seo.json` содержит абсолютный `base_url`, название сайта, необязательные токены подтверждения и редакторские переопределения для отдельных страниц. Остальные descriptions автоматически составляются из заголовка и первого содержательного абзаца **готового HTML**. Они обрезаются по границе слова; для слишком общего вступления задайте отдельное описание в `pages`. Список страниц вручную не поддерживается.

Для каждой главы добавляются уникальный title и description, абсолютный canonical, Open Graph, Twitter Card и JSON-LD. Язык `ru` берётся из конфигурации mdBook. Карточка использует существующий баннер проекта, преобразованный в `assets/social-card.png`; новая клиентская SEO-библиотека не загружается. `meta keywords` не используются.

Структурированные данные описывают книгу на титульных страницах, технические статьи в главах и хлебные крошки. Авторы берутся из соответствующего `book.toml`. Рейтинги, отзывы, даты и награды не выдумываются. Наличие JSON-LD не гарантирует расширенный результат в поиске.

Уровни заголовков нормализуются только в сгенерированном HTML: первый заголовок становится H1, следующие — H2 и ниже без пропуска уровня. Название в панели навигации становится обычным элементом. Русские исходники, английские якоря, видимый код и контрольные данные оригинала сохраняются.

## Canonical и дубли

Основная страница `/` и её копия `title-page.html` имеют canonical на `/russian-rustbook/`. Аналогично работают `/extras/bits-bytes/` и `00-about.html`. Имена первых глав определяются из актуального SUMMARY. Старые URL продолжают открываться: перенаправления и переименование глав не нужны.

Остальные главы имеют canonical на собственный URL. `print.html`, `toc.html` и `404.html` получают `noindex, follow` и не имеют canonical на чужое содержимое. Для дубликата титульной страницы используется canonical без противоречащего ему noindex.

`site-url` в обоих `book.toml` отвечает за пути ресурсов и 404 mdBook; абсолютные SEO-адреса задаются `base_url`. При смене адреса обновляйте все три значения вместе.

## Sitemap и robots.txt

`book/sitemap.xml` автоматически извлекается из реально собранных HTML-файлов обеих книг. Включаются только уникальные canonical-страницы; печатная книга, iframe оглавления, 404 и копии титульных страниц исключаются. Используются абсолютные HTTPS URL с `/russian-rustbook/`. `lastmod` не записывается: время сборки не является датой изменения содержания, а надёжного учёта всех зависимостей страницы пока нет.

В CI XML разбирается стандартной библиотекой Python, проверяются namespace, отсутствие дублей и точное соответствие sitemap индексируемым страницам. Это семантическая проверка XML, а не загрузка внешней XSD.

Файл `/russian-rustbook/robots.txt` — информационная копия с `Allow: /` и ссылкой на sitemap. **Поисковые роботы запрашивают `/robots.txt` в корне хоста; файл в подкаталоге не управляет обходом.** Если нужен корневой файл, добавьте его в отдельный репозиторий `Waikizashi/waikizashi.github.io`, не блокируя остальные проекты на хосте. Отсутствие robots.txt обычно не запрещает индексацию. Sitemap отправляйте напрямую в панели поисковых систем.

## Добавление главы и локальные проверки

1. Для оригинальной главы используйте процесс [UPDATING.md](UPDATING.md). Самостоятельные материалы держите отдельно от официального перевода.
2. Добавьте ссылку в нужный SUMMARY; пишите понятный заголовок и содержательный первый абзац, у изображений — описательный alt.
3. При необходимости добавьте описание в `config/seo.json` по относительному HTML-пути, например `ch04-02-references-and-borrowing.html`. Для дополнения путь начинается с `extras/bits-bytes/`.
4. Выполните:

```sh
bash scripts/install_mdbook.sh
python3 scripts/build_site.py
python3 -m unittest discover -s tests -p test_site.py -v
```

В CI дополнительно запускаются проверки браузером и Lighthouse; подробности в [DEPLOYMENT.md](DEPLOYMENT.md). Проверяются ресурсы HTML и CSS, ссылки и якоря, URL в базовом пути, уникальность метаданных, H1, порядок заголовков, alt, JSON-LD и sitemap. Результаты — `dist/site-verification.json` и `dist/seo-verification.json`. Эти проверки не оценивают смысл перевода и качество каждого описания: их нужно читать при редактуре.

## Google Search Console

1. Откройте https://search.google.com/search-console/ и добавьте **ресурс с префиксом URL**: `https://waikizashi.github.io/russian-rustbook/`. Для Domain property нужен контроль DNS домена `github.io`, которого у владельца проекта нет.
2. Выберите подтверждение через HTML-тег. Из выданного Google тега скопируйте только значение `content` в `verification.google` файла `config/seo.json`. Не вставляйте целый HTML-тег и не используйте пример токена.
3. Объедините изменение в main, дождитесь успешного CI и Pages. Проверьте исходный HTML главной страницы: в `<head>` должен присутствовать `google-site-verification` с вашим значением.
4. Нажмите «Подтвердить» в Search Console. Не удаляйте токен после проверки: Google проверяет его повторно.
5. В разделе Sitemaps отправьте `https://waikizashi.github.io/russian-rustbook/sitemap.xml`.
6. В URL Inspection проверьте главную и несколько глав, выполните проверку опубликованного URL. Если страница доступна и подходит для индексации, запросите индексацию. Это запрос, а не гарантия включения.
7. Смотрите Pages/«Индексирование страниц»: причины исключения, ошибки обхода, выбранный Google canonical. Технические страницы и копия титульной страницы ожидаемо не должны конкурировать с главами.
8. В Performance/«Эффективность» отслеживайте запросы, показы, клики, CTR и среднюю позицию, фильтруйте по странице и сравнивайте периоды. Это данные переходов из Google, а не статистика всех посещений сайта.

## Bing Webmaster Tools

1. Откройте https://www.bing.com/webmasters/ и добавьте тот же URL. Если интерфейс предлагает импорт подтверждённого ресурса из Google Search Console, можно использовать его.
2. При ручной проверке выберите HTML meta tag. Поместите только значение `content` тега `msvalidate.01` в `verification.bing` файла `config/seo.json`.
3. Опубликуйте изменение, проверьте тег в исходнике главной и завершите подтверждение в Bing.
4. Отправьте тот же sitemap в Sitemaps. Используйте URL Inspection и Site Explorer для диагностики, Search Performance — для поисковых запросов и кликов.

Ни подтверждение аккаунтов, ни отправка sitemap не выполняются автоматически этим проектом. Реальные токены должен выдать соответствующий сервис владельцу.

## Диагностика и развитие

- **404/ресурсы из корня:** проверьте оба `site-url`, `base_url` и результат общего сборщика.
- **Старые meta:** убедитесь, что развёрнут последний main; откройте исходник HTML, а не только DOM после JavaScript. Canonical и descriptions не зависят от JavaScript.
- **Страница исключена:** проверьте HTTP-статус, robots хоста, meta robots, canonical и включение в sitemap. Для дубликата титула это ожидаемо.
- **Просканировано, но не проиндексировано:** проверьте полезность и уникальность текста, внутренние ссылки и отличие от других переводов. Решение об индексации принимает поисковая система.
- **Нет показов:** дождитесь обхода, проверяйте Performance и доступность страниц; не делайте выводов только по оператору `site:`.

Продвигайте проект через полезные материалы об ownership, borrowing, async и двоичных форматах, исправления и участие в русскоязычном Rust-сообществе. Ссылайтесь на конкретные главы по теме, избегайте покупных ссылок и массового спама. Сначала улучшайте точность перевода и практическую ценность. Позиции и сроки индексации не гарантируются.

Персональная аналитика и сторонние трекеры не добавлены. Search Console/Bing показывают поисковые переходы; для анализа дальнейших действий на сайте нужен отдельный осознанный выбор аналитики.
