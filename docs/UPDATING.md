# Как обновлять книгу вслед за оригиналом

Процесс сохраняет русский текст и показывает только требующие внимания места. Подготовка изменений не переводит главы, не меняет опубликованный commit и не перезаписывает `src/`.

## 1. Подготовить изменения

Работайте в отдельной Git-ветке. Требуются Git, Python 3.11.8+ и Pandoc 3.x.

```sh
git switch -c update-rustbook
python3 scripts/check_upstream.py
python3 scripts/upstream.py prepare --ref HEAD --output .updates/next
```

`HEAD` один раз разрешается в точный hash; все дальнейшие действия относятся к нему. Можно передать конкретный commit вместо HEAD. Репозиторий оригинала кэшируется в `.cache/`; исходники извлекаются через `git archive`, код из них не исполняется.

Для работы без сети можно передать уже полученные официальные исходники:

```sh
python3 scripts/upstream.py prepare \
  --source /path/to/official-book \
  --commit FULL_OFFICIAL_COMMIT \
  --output .updates/next
```

В этом режиме редактор отвечает за соответствие каталога указанному commit. Обычный сетевой режим получает исходники непосредственно из Git по hash.

## 2. Прочитать отчёт

В `.updates/next/` находятся:

- `REPORT.md` — таблица изменённых и добавленных глав, удаления и изменение порядка.
- `plan.json` — подробные признаки изменения текста, видимого кода и зависимостей.
- `diffs/*.diff` — построчное сравнение английского Markdown и развёрнутых листингов.
- `code/*.txt` — полный новый видимый код и вывод изменённых глав с нумерацией блоков.
- `upstream/en/` — новая английская версия; `images/` — её рисунки.
- `verification/official-*.json` — новые контрольные данные, полученные из оригинала.
- `SUMMARY.template.md` — новый порядок с сохранёнными русскими названиями; у новых файлов стоит `TODO`.
- `translation-state.json` — состояние проверки глав этого кандидата.

Если изменился только подключённый `output.txt` или `.rs`, отчёт всё равно укажет затронутую главу. Изменения скрытых строк и неиспользуемых частей подключённого файла тоже видны как изменение зависимости; видимый код может при этом остаться прежним.

Кандидат не перезаписывается повторным `prepare`. Для другой версии выберите новый каталог. До принятия все действия можно отменить, оставив основную редакцию на прежнем commit.

## 3. Обновить русские главы

Правьте только затронутые файлы в `src/`. Сохраните качественный неизменившийся перевод. Изменившийся смысл переведите по новому оригиналу, код и диагностический вывод перенесите без перевода.

При новых или удалённых разделах обновите `src/SUMMARY.md` по шаблону, переведите названия и сохраните отдельный раздел дополнений. Новые уровни заголовков и их английские идентификаторы перечислены в `verification/official-headings.json` кандидата. Перед каждым русским заголовком должен находиться якорь вида `<a id="original-english-id"></a>`.

Новые главы получают официальные имена файлов. Удалённый русский текст остаётся доступен в истории Git. При изменении изображений проверьте подпись и русское текстовое описание; принятие кандидата перенесёт официальные файлы рисунков в `src/img/`.

## 4. Зафиксировать проверку по главам

После содержательной проверки каждой затронутой главы:

```sh
python3 scripts/upstream.py review --plan .updates/next ch03-02-data-types.md
```

Можно перечислить несколько файлов. Команда проверит код, уровни заголовков и якоря, затем запишет явное решение редактора. Она не делает перевод и не подтверждает его качество вместо человека. Неизменившиеся главы сохраняют прежнюю запись проверки.

Если видимый текст не изменился, но изменился hash зависимости, проверьте изменение и отметьте главу той же командой. Пропускать такие изменения автоматически инструмент не будет.

## 5. Принять и проверить всю книгу

```sh
python3 scripts/check_book.py --candidate .updates/next
python3 scripts/upstream.py accept --plan .updates/next
python3 scripts/check_book.py
python3 scripts/check_language.py
python3 -m unittest discover -s tests -v
```

Принятие блокируется, если хоть одна глава не проверена, нарушен порядок, отсутствует перевод, изменён код или сломаны локальные ссылки. План со старой базой также отклоняется. `accept` переносит контрольные данные, английский снимок, записи проверки и изображения; русский текст не перезаписывает. Файл зафиксированной версии обновляется последним.

Проверьте Git diff. Обновите README, CHANGELOG и VALIDATION: версии, новые темы, количество глав/разделов и фактически выполненные проверки. Исторические отчёты прежних выпусков не переписывайте задним числом.

## 6. Собрать выпуск

Пересоберите EPUB/Markdown, проверьте EPUBCheck, затем PDF и обе части сайта по [BUILDING.md](../BUILDING.md). Проверьте страницы PDF, оглавление и иллюстрации. Обновите `downloads/SHA256SUMS`. Если новое имя выпускных файлов требует другого года, измените `config/publication.json`.

После успешного CI можно создать тег `v*`; workflow выпуска пересоберёт форматы и опубликует их в Releases. Сайт и электронные файлы собираются из тех же русских глав.

## Автоматическое наблюдение

Еженедельный `upstream.yml` и его ручной запуск сравнивают официальный HEAD с зафиксированным commit. При новой версии автоматически подготавливаются отчёт по главам, diff, снимок и состояние кандидата; результат сохраняется как артефакт GitHub Actions. Workflow не меняет основной перевод и не принимает новую версию без проверки редактора.

Тесты инструментов покрывают изменения подключённого кода, текста и структуры; запрет непроверенного обновления, устаревшего плана и перезаписи кандидата; сохранность русских глав при принятии.
