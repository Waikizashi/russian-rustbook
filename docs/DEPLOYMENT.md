# Сборка и публикация GitHub Pages

Публичный адрес: https://waikizashi.github.io/russian-rustbook/.

## Единая команда

На Linux x86-64:

```sh
bash scripts/install_mdbook.sh
python3 scripts/build_site.py
```

Используется **mdBook 0.5.4**, официальный архив и закреплённый SHA-256. Можно установить эту же версию через Cargo по [BUILDING.md](../BUILDING.md). Сборщик проверяет версию и отказывается запускать другую. Для сборки и проверок сайта нужны Python 3.11+ и Node.js 24.11.1 (пересборка поискового индекса); Pandoc и Rust нужны для остальных проверок проекта.

Сборщик создаёт `book/`, готовит отдельные исходники дополнения в `.book-src`, собирает его в `book/extras/bits-bytes/`, добавляет SEO и проверяет весь результат. Относительный `--dest-dir` mdBook зависит от рабочей директории процесса; общий скрипт использует абсолютный путь, чтобы не разместить дополнение вне общего сайта.

HTML остаётся статическим: чтение текста работает без JavaScript, поиск и переключение тем используют штатный JavaScript mdBook. К штатному поисковому движку добавлена небольшая Unicode-функция обработки слов; индекс пересобирается заранее, а не в браузере читателя. Печатные страницы сохранены.

## Workflows и права

`ci.yml` запускается для PR, push в main и вручную:

- `site`: сборка двух книг, ссылки, SEO и sitemap; Chromium проверяет все 126 страниц при ширине 390 px и отдельные таблицы/парсер при 320 и 768 px, поиск, темы, навигацию и редактирование; Lighthouse 13.6.0 измеряет мобильную главную; сохраняет отчёты. Pages-артефакт загружается только для main.
- `book`: тесты процесса обновления, контроль официальной структуры/кода, проверка языка, примеры mdBook, обе EPUB и EPUBCheck.
- `supplement`: fmt, clippy, тесты и 27 программ дополнения на минимальной версии Rust 1.85.0 и текущем stable. Stable намеренно проверяет совместимость с будущими обновлениями, а не фиксирует воспроизводимую версию выпуска.
- `deploy`: только после успеха **всех** перечисленных jobs, только для main; вызывает reusable workflow `pages.yml`.

`pages.yml` использует официальные configure-pages, upload-pages-artifact (в CI) и deploy-pages. Deploy получает только `pages: write` и `id-token: write`; исходники и PR-код в нём не исполняются. Проверки PR имеют `contents: read`, checkout не сохраняет учётные данные. `pull_request_target` не используется. Actions закреплены полными commit SHA.

Concurrency отменяет устаревшие проверки PR; публикации сериализуются группой `pages` без отмены текущего deployment. Есть ограничения времени jobs. Проверенные инструменты EPUB кэшируются по хешам установочных скриптов. EPUB и сайт передаются через артефакты, не через коммиты сборочных каталогов.

`upstream.yml` отдельно наблюдает за оригиналом и сохраняет кандидата обновления, не записывая перевод. `release.yml` собирает офлайн-файлы по тегу `v*`; `links.yml` проверяет внешние ссылки дополнения по расписанию. Сбой внешнего сайта не должен блокировать публикацию локально корректной книги.

## Настройки репозитория

В **Settings → Pages → Build and deployment → Source** должно быть **GitHub Actions**. Настройка уже работала при первоначальном аудите; наличие нового workflow само по себе не является подтверждением нового deployment. В Actions смотрите job `deploy / deploy` и его URL. Если окружение `github-pages` требует approval, его должен одобрить владелец.

Для защиты main можно выбрать проверки `site`, `book` и оба варианта `supplement` обязательными в ruleset. Не добавляйте `deploy` как обязательную PR-проверку: он запускается после объединения в main.

About на странице репозитория (шестерёнка справа):

- Description: `Rust Book на русском: руководство по Rust с примерами, ownership, borrowing и async. mdBook и практическое дополнение о битах и байтах.`
- Website: `https://waikizashi.github.io/russian-rustbook/`
- Topics: `rust`, `rust-lang`, `rustbook`, `rust-tutorial`, `mdbook`, `russian-translation`, `rust-learning`.

Если подключённый GitHub API не предоставляет редактирование этих полей, измените их через интерфейс. Эти поля не заменяют SEO отдельных HTML-страниц.

## Проверка опубликованной версии

1. Успешный workflow должен относиться к нужному commit main; PR только проверяется и не публикуется.
2. Откройте главную, главу о заимствовании и дополнение. Проверьте навигацию, поиск обеих книг, темы и ссылки редактирования.
3. Загрузите `sitemap.xml` и проверьте абсолютные URL. Посмотрите исходник главы: canonical должен вести на неё, а не на корень хоста.
4. Несуществующий вложенный URL должен отдать 404 с ресурсами из правильного `/russian-rustbook/`.

Для локального HTTP-просмотра с настоящим базовым путём создайте вне репозитория каталог `preview`, в нём ссылку `russian-rustbook` на абсолютный путь `book/`, затем запустите `python3 -m http.server --directory preview 8765`. Откройте `/russian-rustbook/`. Для мобильной проверки используйте ширины 320, 390 и 768 px, широкие таблицы и код должны прокручиваться внутри колонки, а не расширять всю страницу.

## Откат и типовые ошибки

При ошибке сборки новый Pages-артефакт не разворачивается, предыдущий сайт продолжает работать. Для отката опубликованного изменения создайте обычный `git revert` соответствующего commit в новой ветке, пройдите CI и объедините PR. Историю не переписывайте. Для повторной публикации текущего main вручную запустите **Проверки → Run workflow → main**.

- **mdBook: другая версия:** установите 0.5.4; не обновляйте генератор без проверки обеих книг и SEO.
- **Не найдены изображения:** восстановите исходные файлы из проверенной версии, проверьте `check_book.py`; не удаляйте ссылки или главы ради зелёного CI.
- **Checksum mismatch:** не отключайте проверку; сверьте архив с официальным релизом и обновляйте checksum только после проверки.
- **Ошибка установки Pandoc:** используется закреплённый официальный архив, apt-зеркала не нужны.
- **Deploy skipped:** проверьте результаты всех jobs и ветку; PR не публикуются.
- **Pages permission/environment:** проверьте Source, `github-pages` и правила окружения; не расширяйте токен проверок PR.
- **SEO validation failed:** прочитайте JSON-отчёт в артефакте `site-validation`, исправьте источник/описание/путь и пересоберите.

## Браузерный аудит

Только в CI для контроля качества устанавливаются Lighthouse 13.6.0 и Playwright 1.56.1 из npm под Node 24.11.1. Эти зависимости не попадают в опубликованный сайт. Используется Chrome runner, браузер дополнительно не скачивается. Отчёты Lighthouse, результаты браузерной проверки и скриншоты доступны в артефакте `site-validation` даже при сбое аудита. SEO и accessibility Lighthouse должны быть не ниже 90; нестабильные замеры скорости сохраняются без жёсткого порога. Ошибки загрузки ресурсов, JavaScript и горизонтальная прокрутка страницы блокируют публикацию.

В некоторых изолированных средах Chromium не может создать системный сокет. Это ограничение среды, не измерение сайта; запускать аудит следует на runner или локальной машине, поддерживающей Chromium.
