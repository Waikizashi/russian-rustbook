# Структура проекта

Основная книга — редактируемые русские главы, а EPUB, PDF и сайт — результаты их сборки. Для исправления одного абзаца не нужно пересобирать перевод целиком или редактировать электронный архив.

| Путь | Назначение |
|---|---|
| `src/*.md` | Русский текст, по одному файлу на официальный исходный файл |
| `src/SUMMARY.md` | Порядок и вложенность глав mdBook |
| `src/img/` | Иллюстрации оригинала |
| `upstream.json` | Зафиксированные commit, Rust/edition, дата сверки и контрольные количества |
| `upstream/en/` | Английские исходники зафиксированной редакции для построчного сравнения; include-макросы оригинала сохранены |
| `upstream/manifest.json` | Отпечатки текста, видимого кода и зависимостей каждой главы |
| `translation-state.json` | До какой версии исходника проверена каждая русская глава |
| `verification/official-*.json` | Автоматически извлечённые порядок, заголовки и точный видимый код |
| `verification/` | Отчёты конкретных проверенных выпусков и исходной сверки переводов |
| `config/publication.json` | Название, авторы, язык и общее имя файлов EPUB/PDF/Markdown |
| `assets/` | Оформление репозитория, сайта и электронного издания |
| `scripts/official.py` | Адаптер формата оригинала: Listing, include, rustdoc_include, скрытые строки |
| `scripts/upstream.py` | Подготовка изменения, запись проверки глав и принятие новой версии |
| `scripts/check_*.py`, `verify_epub.py` | Проверки исходников, языка, сайта и EPUB |
| `scripts/build_ebooks.py`, `build_pdf.py` | Общая сборка форматов из русских глав |
| `extras/bits-bytes/` | Самостоятельное дополнение, со своим Cargo workspace и примерами |
| `tests/` | Проверки сценариев обновления оригинала |
| `.github/workflows/` | CI, сайт, выпуск файлов и наблюдение за оригиналом |

`book/`, `dist/`, `.cache/` и `.updates/` — генерируемые каталоги, они не входят в исходный код. Кандидат обновления хранит собственное состояние проверки; повторная подготовка в тот же каталог запрещена, чтобы не затереть работу. Для совместной работы можно выбрать другой каталог, сохранить его в рабочей ветке или передать подготовленный архив.

## Границы изменений

Редактура перевода затрагивает `src/`; официальные примеры и английские якоря остаются прежними. Обновление оригинала проходит через отдельный кандидат и проверку затронутых глав. Параметры выпуска задаются в одном JSON, оформление — в CSS. Новое самостоятельное дополнение размещается в `extras/<имя>/` и получает отдельный пункт в оглавлении.

Основная книга и дополнения не используют общий Cargo workspace: намеренно ошибочные примеры официальной книги нельзя проверять как исполняемые программы дополнения. Сайт собирает их вместе, но порядок официальных глав проверяется отдельно.

## Что считается проверенной главой

Запись в `translation-state.json` связывает русскую главу с отпечатком английского исходника и его зависимостей. Если меняется подключённый Rust-файл, вывод компилятора или рисунок, глава попадает в отчёт даже при неизменном Markdown. Исходный commit и дата проверки сохраняются отдельно для каждой главы; неизменившиеся главы не требуют повторного перевода.

Смысл перевода проверяет редактор. Команда `review` записывает его явное решение и дополнительно сверяет код, уровни заголовков и якоря. Она не оценивает качество языка автоматически. Обычная последующая редактура русского текста допустима; сохранённый hash русской версии служит для истории проверки, а не запрещает правки.

## Расширение инструментов

Для нового синтаксиса официального mdBook изменяется адаптер `official.py` и добавляется тест. Для нового экспортного формата добавляется отдельный сборщик, использующий ту же конфигурацию и русские исходники. Число файлов, заголовков, блоков кода, версия Rust и edition берутся из данных; добавление главы не требует изменения констант в проверках.

Порядок обновления: [UPDATING.md](UPDATING.md). Сборка: [BUILDING.md](../BUILDING.md).

## Сайт и поисковые системы

`scripts/build_site.py` собирает обе книги, `site_seo.py` дополняет HTML, `check_site.py` и `check_seo.py` проверяют результат. `config/seo.json` задаёт публичный адрес, редакторские описания и токены подтверждения. Встроенные пути ресурсов задаются в обоих `book.toml`. Новые главы обнаруживаются из сборки, поэтому список URL для sitemap не дублируется вручную. Подробнее: [SEO.md](SEO.md), [DEPLOYMENT.md](DEPLOYMENT.md), [MAINTENANCE.md](MAINTENANCE.md).
